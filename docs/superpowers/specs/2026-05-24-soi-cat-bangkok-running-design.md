# 설계: 소이캣의 방콕 러닝 (Wat Run? v2)

> **날짜:** 2026-05-24
> **상태:** 승인됨 (브레인스토밍 → 설계 확정, 구현 계획 작성 대기)
> **대상 저장소:** RunReady (Threads 봇, TypeScript)

---

## 1. 배경 & 문제

현재 봇(v1)은 방콕 한국인 러너 커뮤니티(김치팍치)를 위한 **날씨·운동 유틸리티**다.
하루 2회(04:00 오늘의 컨디션, 18:00 내일의 운동) KO 본문 + EN/TH 답글로 Threads에 게시한다.

오너 피드백:
1. **효과가 없다** — 게시물이 성장에 기여하지 못한다.
2. **오전 날씨·공기 정보가 부정확하다.**

### 핵심 목표 (브레인스토밍에서 확정)
- **목표:** 발견·팔로워 성장 (낯선 사람이 계정을 발견하고 팔로우)
- **타깃:** 방콕 라이프·관광객 (러닝을 렌즈로 한 가장 넓은 도달)
- **재량:** 포맷·주기 자유롭게 재설계 (자동화는 유지)

### 진단
"날씨봇"은 본질적으로 발견되지 않는다(아무도 날씨봇을 새로 찾아 팔로우하지 않음).
성장은 **"왜 팔로우하지?"**에 답해야 한다 → 답은 **캐릭터**(팔로우 이유)와 **장소**(발견·저장·공유).

---

## 2. 콘셉트

> 방콕 길거리 고양이 **소이캣(Soi Cat)** 이 매일 *오늘 뛰기 좋은 방콕의 한 곳*을 골라주고,
> 정확한 컨디션과 따뜻한 한마디를 건넨다. 하루하루가 모이면 **방콕 러닝 지도**가 완성된다.

- **캐릭터 톤:** 다정한 코치 (따뜻하게 응원, 진입장벽 낮음, 무리 권하지 않음). 시니컬/츤데레 아님.
- **두 축:** 캐릭터(팔로우 이유) × 오늘의 스팟(발견·저장·"방콕 가는 친구에게 공유").

---

## 3. 콘텐츠 구조 (하루 2회 유지, 역할 재정의)

| 시간 | 이름 | 내용 |
|------|------|------|
| **오전 (~05:00)** | **오늘의 스팟** (히어로) | 소이캣이 오늘의 장소 1곳 추천 + *그 장소의* 정확한 더위/공기/자외선 + 베스트 창 + 코치 한마디 + 고양이 그림. 저장형 콘텐츠. |
| **오후 (~18:00)** | **가벼운 한 컷** (요일 로테이션) | ① 뛰고 나서 갈 카페·먹킷 ② "내일 어디서 뛸래?" 폴(poll) ③ 소이캣 하이쿠 ④ 방콕 러닝 트리비아. |

**확정 결정:** 기존 **요일별 운동 플랜(인터벌/템포 등)은 은퇴**한다 (발견·관광 목표에 약한 콘텐츠).

## 4. "오늘의 스팟" 시스템

- **스팟 데이터셋 (~30곳):** 실제 방콕 러닝 장소만. 예: 룸피니, 벤짜낏 포레스트파크, 벤짜시리,
  짜뚜짝, 롯파이(철도공원), 수안루앙 라마9, 총논시 운하공원, 짜오프라야 스카이파크, 강변 루트,
  방까쩌("방콕의 허파"), 프린세스마더 기념공원 등.
- **각 스팟 필드:** `이름(KO/EN/TH) · 지역 · 한줄소개 · 좌표(lat/lng) · 루프거리 · 그늘점수 · 가장 가까운 Air4Thai 측정소`.
- **로테이션:** 날짜 기반 1일 1곳(연속 반복 없음). 비 예보 시 그늘/지붕 많은 스팟 우선.
- **수집 요소:** 다녀간 스팟이 쌓이면 고정(pinned) **"방콕 러닝 지도" 스레드**로 모음 → 신규 방문자 onboarding. *(v2 초기 범위 밖, 후속 단계)*

## 5. 정확도 재건 (부정확 문제 해결)

> **구현 계획 단계 검증 결과 (2026-05-24):** Air4Thai(`air4thai.pcd.go.th`)는 **TLS 인증서가 만료**되어
> 의존 시 인증서 검증을 꺼야 함(보안 안티패턴). 따라서 공식 PCD 대신 **WAQI 스팟별 조회**로 결정.
> WAQI는 v1에서 이미 방콕 정확도가 검증됐고, geo 피드가 좌표 기준 *가장 가까운 측정소*를 자동 반환한다.

- **공기질:** **WAQI geo 피드를 스팟 좌표로 조회** → 그 장소에서 가장 가까운 측정소의 실제 PM2.5 AQI + 측정소명.
  기존 `data/airQuality.ts`(WAQI) 재활용·좌표 파라미터화. (Air4Thai는 인증서 정상화 시 후속 옵션.)
- **날씨·UV·강수:** **Open-Meteo** (무료·카드 불필요·시간별, 검증 완료: temp/humidity/uv_index/precipitation_probability,
  로컬 ISO 시각). OpenWeather **완전 대체** → 키/카드 의존 제거.
- **비 nowcast:** Open-Meteo 강수확률로 "오전 6–7시 소나기 가능 — 우산 챙겨요" 힌트 라인.
- **재사용:** 기존 WBGT·라벨·베스트창(analyzeBand) 로직 유지, **입력 소스만 교체**.

## 6. 언어 · 발견 전략

- **한국어 본문이 히어로** (고양이 그림 포함) — 김치팍치 정체성 유지.
- **EN·TH는 댓글에 묻지 않고 독립 포스트/강한 답글 + 각자 토픽 태그**로 게시 → 발견력 확보.
- **토픽 태그:** `#방콕러닝 #BangkokRunning #วิ่งกรุงเทพ` + 스팟명.
- **저장형 레이아웃** + 가끔 **폴(poll)** 로 참여율 → 알고리즘 노출.

> **언어 전략 트레이드오프(명시):** 타깃은 관광·라이프(영어/태국어 친화)지만 오너 결정으로 **한국어 전면** 유지.
> 김치팍치를 심장으로 두되 EN/TH 독립+태그로 도달 확장. 성장 데이터가 정당화하면 후속에 리드 언어 전환 가능.

## 8. 아키텍처 (기존 구조 재활용)

- **재사용:** `logic/`(wbgt·labels·goldenWindow·bands), `util/time`, `message/translate`+`validate`,
  `message/images`, `threads/chain`(언어 독립화로 소폭 수정), 코드 내 날짜 계산.
- **교체:** `data/weather`(OpenWeather) → `data/openMeteo`; `data/airQuality`(WAQI) **좌표 파라미터화**(스팟별 조회, `fetchSpotAir`).
- **신규:**
  - `content/spots.ts` — 스팟 데이터셋(+가장 가까운 측정소 매핑)
  - `content/coachLines.ts` — 소이캣 다정한 코치 멘트(요일/상황 로테이션)
  - `message/spotTemplate.ts` — 오전 스팟 포스트 조립
  - `message/eveningRotation.ts` — 오후 요일별 가벼운 콘텐츠
- **은퇴:** OpenWeather 키/의존, 요일별 운동 플랜(`content/workout.ts` + `message/evening*`의 운동 부분).

### 유지 vs 변경 요약
- **유지:** 고양이 그림 로테이션 · KO/EN/TH + 번역 검증 · 코드 내 날짜 · 스레드 체이닝 · 더위/공기 등급 로직
- **변경:** 데이터 소스 · 콘텐츠 초점(추상 날씨 → 오늘의 스팟) · 카피 보이스(소이캣 코치) · 언어 구조(독립+태그)
